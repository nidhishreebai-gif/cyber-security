PROJECT DOCUMENTATION

About the project

A student-friendly offline machine-learning workflow for labeled IP traffic records.

OVERVIEW

Purpose & objectives

Traffic Sentinel demonstrates how supervised machine learning can classify unidirectional flow records into normal or suspicious categories. It provides CSV validation, preprocessing, Random Forest training, held-out evaluation, and a responsive analysis dashboard.

System architecture

CSV upload→Validation & preprocessing→Train / test split→Random Forest→Dashboard & alerts

Label mapping

Labels named BENIGN, Normal, normal traffic, non-attack, or numeric zero map to Normal. Other non-empty label values map to Suspicious. Original labels are retained for evaluation context. Review your dataset's label definitions before training.

Feature preparation

Numeric fields are imputed with training-set medians; categorical fields are imputed with the most frequent training value and one-hot encoded. The selected target, known identifier fields (such as IP addresses and flow IDs), timestamp fields, label-like fields, and high-cardinality text are excluded. The transformer is fitted only on the training partition.

RESPONSIBLE USE

Limitations

  • Predictions are model outputs and do not prove a cyberattack.
  • Results depend on data quality, dataset provenance, labels, and how well the held-out split reflects future data.
  • Random row splitting can allow related flows to appear in both train and test sets; results may overstate generalization when records are correlated.
  • Accuracy alone can be misleading on imbalanced datasets.
  • This project analyzes uploaded offline data only. It does not capture traffic, send alerts externally, or provide calibrated probability scores.
